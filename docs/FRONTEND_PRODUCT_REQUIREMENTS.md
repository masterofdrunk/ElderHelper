# ElderHelper 前端产品需求文档

> 版本：v1.0（基于当前 Android 本地优先能力）
> 目标：为视觉、交互和 Android 前端实现提供同一份页面设计依据。

## 1. 产品定位

ElderHelper 是面向老年人的本地优先手机助手。用户通过一个始终可找到的悬浮按钮说出问题，例如“无线网络在哪里”“怎么给女儿发照片”，应用优先使用本机规则、应用流程和离线知识库给出短步骤；只有本地信息不足时才调用端侧看屏模型。默认不上传语音、截图、识别文字或问题内容。

前端的核心职责不是展示“AI 很强”，而是让用户在紧张、看不清、不会操作时仍然知道：**现在能做什么、下一步点哪里、失败后怎么办、数据是否安全。**

## 2. 目标用户

| 用户 | 特征与诉求 | 设计重点 |
| --- | --- | --- |
| 老年用户（主用户） | 视力下降、对手机层级不熟悉、怕点错或被骗 | 大字、大按钮、单一主操作、明确风险提示、可重复播放 |
| 子女/家属（辅助用户） | 帮助首次设置、想教会一个常用动作、关注隐私 | 明确授权说明、可审核“教我一次”、可一键清除数据 |
| 照护人员（次要用户） | 协助就医、出行、紧急情况 | 快速进入、可解释的边界、紧急操作优先 |

不面向追求复杂自动化的技术用户；不设计代替用户付款、转账、登录、身份认证或医疗判断的流程。

## 3. 核心使用场景

1. **首次准备**：安装轻量 APK 后，一次下载离线语音与看屏模型，完成录音、悬浮窗、看屏和可选“快速看屏”授权。
2. **临时求助**：用户正在微信、设置、地图等页面，点击悬浮按钮说出问题，得到一句结论和不超过三步的操作。
3. **找不到/没听清**：用户说“没找到”“再说一遍”“返回”，无需再次调用模型即可恢复、重复或结束任务。
4. **高风险提醒**：付款、验证码、远程协助、退款、可疑中奖、紧急情况等场景，优先给出停止操作或求助指引。
5. **教会助手常用动作**：用户或家属主动打开“教我一次”，完成低风险操作，审核后保存为本机可复用流程。
6. **离线与隐私管理**：查看模型是否就绪、占用空间、下载进度、删除模型与已学习流程，阅读数据边界。

## 4. 信息架构与导航

采用“**首页分流 + 功能中心 + 具体操作页**”的三级结构。首页不堆放下载、删除、教学和隐私等所有按钮；每个中心只解决一类问题。底部不使用复杂 Tab，固定使用顶部返回和首页入口，避免老年用户在多个平级栏目之间迷路。

```text
L0 启动与首次准备
└─ 欢迎 / 离线能力准备

L1 首页（只做状态与分流）
├─ 开启助手
├─ 使用帮助
├─ 离线能力
└─ 我的与安全

L2 功能中心
├─ 开启助手中心
│  ├─ 录音权限
│  ├─ 悬浮窗权限
│  ├─ 屏幕捕获权限
│  └─ 快速看屏（可选）
├─ 使用帮助中心
│  ├─ 常见问题与能力范围
│  └─ 教我一次
├─ 离线能力中心
│  ├─ 下载 / 更新状态
│  └─ 存储空间管理
└─ 我的与安全中心
   ├─ 隐私与学习说明
   ├─ 已学习操作
   └─ 数据清理

L3 具体操作
├─ 下载详情 / 下载失败 / 网络确认
├─ 删除模型确认
├─ 学习录制中 → 审核保存
├─ 已学习操作详情 / 删除确认
└─ 系统设置外跳说明页

任意其他 App
└─ 悬浮助手（独立于上述页面）
   ├─ 待命
   ├─ 录音中
   ├─ 本地分析 / 看屏中
   ├─ 语音指引 + 重复刚才的话
   └─ 没找到 / 完成 / 停止
```

导航规则：

- L1 首页只保留一个大主按钮“开启助手/助手正在运行”，其余为 2×2 功能入口卡；
- L2 页面使用标准顶部栏：返回、标题、必要时右侧“帮助”；
- L3 破坏性操作必须通过底部确认弹窗或确认页完成，不能直接执行；
- 从系统设置返回时回到原来的 L2 权限页，而不是直接丢回首页；
- 悬浮助手不承担模型管理或隐私管理，它只承担即时求助。

## 5. 页面列表与模块结构

### P0 首页（助手控制台，L1）

**页面目标**：让用户一眼知道助手是否可用，并只有一个首要动作“开启/继续使用助手”。

模块从上到下：

1. **品牌头部**：`ElderHelper`、一句承诺“陪您轻松使用手机”。不显示技术术语或模型名称。
2. **助手状态主卡**：
   - 标题：“随时开口问，帮您找按钮、看页面”；
   - 状态胶囊：`助手正在运行` / `还差：看屏授权` / `请先下载离线包`；
   - 唯一主按钮：`开启助手`、`继续完成授权` 或 `助手正在运行`。
3. **四个功能入口卡**（2×2）：
   - `开启与授权`：显示缺失权限数量；
   - `使用帮助`：常见问题、教我一次；
   - `离线能力`：模型就绪/下载中与占用空间；
   - `我的与安全`：隐私、已学习操作、数据清理。
4. **轻量说明**：一行“默认在本机处理，不上传语音和截图”，点击进入完整隐私说明。

页面规则：首屏必须包含主状态卡和主按钮；不把重要状态写进 Activity 标题栏；首页不出现删除按钮、不出现多条权限解释、不展示冗长模型明细。

### P1 开启助手中心（L2）

**页面目标**：将“为什么还不能用”变成按顺序完成的四步，不在首页同时展示多个权限按钮。

模块：顶部进度（例如“已完成 2/4”）、权限步骤列表、当前步骤说明卡、单个主按钮“去开启”、辅助入口“为什么需要此权限”。

完成四步后展示完成页：“助手已准备好”，唯一主按钮为“开始使用”。快速看屏属于可跳过的可选步骤，不能阻塞悬浮助手启动。

### P2 使用帮助中心（L2）

模块：

1. **我可以帮什么**：按电话、微信、出行、健康、生活服务、设备设置分组的能力卡；
2. **问法示例**：如“无线网络在哪里”“怎么给家人发照片”；
3. **教我一次**：一张独立卡片，进入学习中心；
4. **紧急帮助**：弱红色入口，说明紧急情况请先拨打 120/110/119。

此页只解释与分流，不承载具体语音任务结果。

### P3 离线能力中心（L2）

**页面目标**：让用户和家属管理模型，不干扰日常使用。

模块：离线语音状态、离线看屏状态、总占用空间、网络状态、`下载/检查更新`入口、`存储空间管理`入口。首页只展示摘要，详细文件、进度和危险操作全部放在此页之后。

### P4 首次离线包下载 / 更新状态（L3）

可作为首页离线能力卡的展开态，也可做独立全屏页。

模块：总大小和可用空间说明、Wi‑Fi/移动网络提醒、总体进度条、当前文件名称、已下载/总大小、暂停按钮、失败原因与“重试”。

关键文案：说明“下载完成后，语音和看屏可离线使用”；不可暗示模型下载后能自动操作所有 App。

### P5 系统权限步骤页（L3）

**建议拆成逐项步骤页，而不是一次抛出系统弹窗。**

每步包含：步骤序号、图标、权限名称、为什么需要、不会做什么、去开启按钮、完成状态。

顺序：录音 → 悬浮窗 → 屏幕捕获 → 快速看屏（可选）。

屏幕捕获必须解释“仅在你提问时读取当前页面”；快速看屏必须说明“系统设置中悬浮按钮可能暂时不可见，返回后继续”。

### P6 悬浮助手（跨 App）

这是产品的核心交互，不是普通按钮。

模块：

- **72dp 圆形主控件**：待命为绿色；录音中显示明显脉冲/红点；处理中显示转圈但不移动位置；
- **状态气泡**：位于按钮下方并左对齐，显示“请说话”“正在看屏”“我没看清”等；
- **结果气泡**：最多三步，支持语音播报；
- **重复刚才的话**：独立大触点；
- **拖拽**：可移动，但始终限制在可见区域，松手自动贴边。

按钮位置不能因状态气泡变宽、文字变长或页面旋转而横向跳动。系统设置有权临时隐藏第三方悬浮窗；不可尝试绕过，应通过通知和返回提示做降级。

### P7 指引结果 / 任务恢复

当前可由悬浮气泡承载，后续可扩展为半屏底部卡片。

模块：任务名称、当前第 1 步、可见按钮/文字引用、风险提示（如有）、三个固定回复入口：`再说一遍`、`没找到`、`结束`。

文本规则：先结论，最多三步；每步一句；不要出现“模型推理”“截图分析”等内部措辞；高风险页面只提示核对，不出现代点确认按钮。

### P8 学习中心（L2）与教我一次：开始/录制中（L3）

模块：可学习范围说明、不可学习范围（支付、登录、身份认证、医疗记录）、当前状态、结束学习按钮、退出按钮。

录制中应显示醒目但不吓人的横幅：“正在学习低风险操作。请先说出目标，再亲自完成点击。” 不显示或保存用户聊天、联系人、密码、验证码、截图。

### P9 教我一次：审核与保存（L3）

模块：用户目标、抽象步骤列表（例如“加号 → 相册 → 发送”）、适用 App、有效条件（相同 App / 版本 / 30 天）、`本人或家属确认并保存`、`不保存`。

确认按钮需为主按钮；不能将原始页面文字、联系人姓名或截图展示为“学习内容”。

### P10 我的与安全中心（L2）

模块：隐私与学习说明入口、已学习操作数量与入口、数据清理入口、离线模型管理入口。页面本身不直接删除任何数据。

### P11 隐私与学习说明（L3）

模块：自定义顶部栏（返回 + 标题）、一句摘要“数据留在您的手机里”、正文分段、可删除学习数据入口。

该页必须有明确返回按钮。当前应用使用无标题栏主题，不能依赖系统 ActionBar。

### P12 已学习操作列表与详情（L3）

列表项只展示操作名称、适用 App、保存日期与有效期，不显示原始聊天内容、联系人或截图。空状态需解释“你还没有教过助手任何操作”，主按钮为“去教我一次”。详情页提供删除入口并二次确认。

### P13 删除确认弹窗（L3）

适用于删除离线模型、删除学习流程、重新下载模型。

模块：明确后果、可释放空间/不可恢复说明、次要按钮`取消`、危险按钮`删除`。删除模型时需提醒“删除后助手无法启动，需重新下载”；不在后台静默执行。

## 6. 视觉风格

关键词：**温和、可靠、清晰、非医疗化、非科技炫技、低压力、可读、家人般陪伴。**

- 主色：沉稳绿色（建议 #157A5B），表示“已准备好 / 可继续”；避免高饱和荧光绿。
- 背景：暖灰白（建议 #F6F8F7）；卡片白色，细描边，不依赖重阴影。
- 风险色：柔和砖红，用于删除、诈骗和高风险提醒；黄色仅用于网络/存储等注意事项。
- 字号：页面主标题 28–30sp，区块标题 20–22sp，正文 17–18sp，按钮 17–19sp；不使用小于 15sp 的关键文案。
- 触点：主按钮至少 60dp，普通按钮至少 52dp；同屏主要操作不超过一个。
- 圆角：卡片 24–28dp，按钮 16–18dp；图标使用熟悉的线性/实心图标，必须配文字。
- 动效：短、稳定、可关闭；录音时可用呼吸动画，处理中用静态进度与文案，避免不停跳动。

## 7. 交互与状态要求

| 情况 | 页面表现 | 用户可做什么 |
| --- | --- | --- |
| 模型未下载 | 主按钮不可启动助手，离线卡解释原因 | 下载完整离线包 |
| 下载中 | 显示总进度、当前文件、暂停 | 暂停；稍后继续 |
| 存储不足 | 明确需要的可用空间 | 去清理 / 返回 |
| 使用移动网络 | 二次确认并说明约 1.6GB | 继续 / 取消 |
| 权限缺失 | 逐项显示缺哪一项，不能只报“启动失败” | 前往授权 |
| 悬浮窗被系统设置遮挡 | 通过系统设置提示与通知说明，返回后恢复 | 返回应用或使用通知 |
| 语音未识别 | “我没有听清，请再说一次” | 再说一次 |
| 本地规则无答案且截图失败 | “我没有获取到当前屏幕” | 重新开启看屏 / 说出可见文字 |
| 高风险操作 | 红色弱警示，不出现自动提交 | 核对、退出、联系家人/官方渠道 |
| 无学习记录 | 不显示空白步骤表 | 解释“教我一次”如何开始 |
| 删除完成 | 简短成功反馈，刷新占用和状态 | 重新下载或返回 |

加载状态不得只显示旋转圈：下载显示百分比和大小；看屏显示“正在看当前页面”；端侧模型耗时较长时允许用户看到“正在分析，可继续等待或稍后再试”。

## 8. 无障碍与适老细则

1. 所有颜色状态必须同时有文字，不能仅靠红绿区分。
2. 每个图标按钮都有内容描述；每个危险动作都需要二次确认。
3. 任何页面都不强制横向滑动；正文行高不低于 1.4。
4. 系统返回键始终可离开二级页或弹窗；隐私页和审核页需有可见返回入口。
5. 不自动朗读过长段落；结果先播报一句结论，用户可点击“重复刚才的话”。
6. 状态变化不能让主要按钮跳位；悬浮按钮的位置必须在状态变化、拖动、旋转后保持可预期。

## 9. 前端验收清单

- 首页首屏能看见当前状态与唯一主操作。
- 录音、悬浮窗、看屏权限均能看出“已完成/未完成”和下一步。
- 模型下载、暂停、失败、存储不足、移动网络、删除、重装均有完整状态。
- 悬浮按钮点击前后不位移，拖不出屏幕，结果可重复播放。
- 系统设置页遮挡悬浮窗时有清晰降级说明；返回后服务不应被应用主动停止。
- 隐私页、学习审核页、删除弹窗都有返回/取消和清晰后果。
- 所有主流程在 1080×2262 设备和较小屏幕上可单手滚动、文字不截断。
